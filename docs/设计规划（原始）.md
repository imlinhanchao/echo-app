## 1. 产品概述

### 1.1 名称与定位

**Echo / 回声** —— 一个跨平台（手机 / 平板 / 桌面 / 鸿蒙）的**听看一体书客户端**。

产品定位在三轮迭代中收敛为一句话：**Echo 是"书"，不是"音乐播放器"**。听书界面的主角是内容与文字上下文，不是封面氛围；进度单位是章节，不是曲目。

### 1.2 核心闭环

Echo 覆盖内容的完整生命周期，而不只是播放：

```
搜索（跨书源聚合）
   │
   ▼
下载（文本入库，加入个人书库）
   │
   ▼
转换为有声书（TTS 转码，产出 音频 + 句级字幕）
   │
   ▼
双形态消费 ──┬── 听：播放器（跟读高亮 / 章节导航 / 睡眠定时）
             └── 看：阅读器（边听边看 / 衬线排版 / 字号调节）
```

两条关键设计推论均由闭环直接推出：

1. **跟读模式免费获得**：TTS 转换必然产出句级字幕（SRT），文本与音频的时间轴对齐数据在转换时顺手生成，无需独立对齐管线；
2. **听与看是同一份资产的两种视图**：下载的文本书直接可读，已转换的书听看双开，当前朗读句在两种视图中共享同一条高亮状态。

### 1.3 生态对接（现有服务，Echo 为其客户端形态）

工作区已有完整的后端与转换生态，Echo 客户端对接而非重建：

| 服务 | 角色 | Echo 侧的对接方式 |
| --- | --- | --- |
| `echo-service`（Go） | Echo 的后端服务：搜书、下书、转有声书；自含转换管线（EPUB → 分句 → TTS → 母带 → SRT → 分章，单块 ≤30 分钟，每块独立 MP3/WAV + SRT + `manifest.json`）；任务持久化队列；App 用 Bearer Token 认证 | Echo 的 API 层。搜索、下载、转换任务的发起与进度轮询全部走其 HTTP 接口；转换在服务端执行，App 是任务客户端 |
| `zlib`（Go） | 图书源插件（Z-Library EAPI 协议纯 Go 实现），`echo-service` 通过 `providers.Provider` 接入，后续可扩展新源 | 客户端无感知，搜索结果的"来源标签"来自 provider 标识；zlib 账号配置在 App 内完成（凭据只存服务端） |
| `tts-service`（局域网 Mac） | Echo TTS 聚合服务：Qwen3-TTS / Kokoro / Edge TTS 统一 HTTP 接口（Apple Silicon/MLX 基础）；`echo-service` 自含转换管线调用它，分句切分保证 SRT 句级粒度 | 跟读高亮的数据保证层。Echo 的"当前句"渲染以 SRT 条目为单位 |
| `tts-service` 代理 | App 不直连 Mac；模型 / 音色 / 试听经 `echo-service` 的 `/api/tts/*` 代理获取 |
| `weread-book-exporter` | 微信读书导出 | 潜在导入通道，Phase 4 评估 |

### 1.4 目标场景

| 端 | 场景 | 体验优先级 |
| --- | --- | --- |
| 手机 | 通勤、运动、家务、睡前 | 单手可达、锁屏/后台播控、离线、睡眠定时 |
| 平板 | 久坐阅读、沙发听读 | 双栏布局、边听边看、手写笔记（后续） |
| 桌面 | 办公背景音、深度笔记 | 多任务、键盘快捷键、时间戳笔记、专注模式 |
| 鸿蒙 | 同手机 + 多设备协同 | 一次适配全量获得，超级终端接力（远期） |

## 2. 信息架构与自适应导航

四个功能域：**书架（听书）、发现、任务中心、我的**；播放器与阅读器是跨域的沉浸层。

### 2.1 三断点（一套代码三种布局）

| 断点 | 宽度 | 设备 | 导航形态 | 播放器形态 |
| --- | --- | --- | --- | --- |
| Compact | < 600dp | 手机、折叠屏外屏 | 底部 Tab Bar（4 项） | 迷你悬浮条 → 全屏播放器（Hero 展开） |
| Medium | 600–1024dp | 竖屏平板、折叠屏内屏 | NavigationRail（窄图标栏） | 底部胶囊播放条（含快捷打点） |
| Expanded | > 1024dp | 横屏平板、macOS/Windows | 完整 Sidebar（图标 + 文字） | 底部全宽播控台 + 右侧笔记面板 |

### 2.2 关键导航路径

- **最短收听路径**：打开 → 书架"正在收听"卡片点播放按钮（1 次点击）；
- **搜转听全链路**：发现/搜索 → 结果行下载按钮 → 任务中心可见转换进度 → 完成即入书架 + 通知点击直达播放；
- **听看切换**：播放器顶栏点封面 ⇄ 阅读器右上角播放按钮，同一位置双向跳转，朗读位置无缝保持。

## 3. 设计系统

Token 全量定义见 [design-tokens.json](design-tokens.json)，此处为规范要点。

### 3.1 设计原则

1. **深色优先（dark-first）**：听读产品的主场景是夜间与沉浸，深色模式为品牌基准态，亮色模式为对偶实现（同一语义 Token 双值）；
2. **8pt 网格**：所有间距取 4 的倍数，基准 8；
3. **语义 Token 三层模型**：primitive（原始色板）→ semantic（light/dark 双值语义层）→ component；组件中禁止裸色值与魔法数字；
4. **层级靠对比不靠色**：标题与正文用 ≥1.5 倍字号差 + 字重区分，禁止单靠颜色区分信息；
5. **动效即反馈**：只动 transform/opacity，100–300ms，ease-out 进 / ease-in 出，遵循 `prefers-reduced-motion`。

### 3.2 色彩

- **Primary**：靛蓝 `#4F46E5`（暗模式提亮为 `#6366F1` 保证对比度）——播放按钮、进行中状态、跟读高亮、选中态；
- **Accent**：暖橙 `#F97316`——封面氛围点缀与"正在播放"动效专用，**不用于可交互状态**，避免状态与意图混淆；
- **Surface 层级**：`base → elevated → subtle` 三级背景构成深度（暗模式下靠层级色不靠阴影）；
- **玻璃拟态**：桌面侧边栏、锁屏播控卡、迷你播放条采用 `blur(20px)` + 70% 透明 surface；
- **阅读器专用**：暖纸深底 `#0B1220` + 米白衬线正文 + 淡靛蓝句子高亮条。

### 3.3 字阶

- 正文基准 `1rem / 行高 1.6`，全局下限 14px；元数据 `0.75rem`；
- 阅读器衬线正文：行长 45–75ch，行高 1.8–2.0，字号可调且跟随系统 Dynamic Type；
- 播放器"当前朗读句"比上下文文字稍大——层级用字号表达。

### 3.4 组件状态机

每个交互元素必须具备完整状态：`default / hover(指针设备) / active / focus-visible / disabled / loading(异步)`。播放控件另有 `playing / paused / buffering` 三态语义。

### 3.5 可访问性门槛

- 触控目标 ≥ 44pt（iOS）/ 48dp（Android）；播放器主按钮 ≥ 56pt；
- 正文对比 4.5:1，UI 控件 3:1，亮暗双模式均验证；
- 键盘全操作 + 焦点环可见；跟读高亮同时是听障与嘈杂环境的可用性方案；
- 图标一律来自图标系统（SF Symbols / Material / Lucide），禁止 emoji 充当 UI 图标。

## 5. 核心交互规范

### 5.1 播放器 v3：四区布局

```
┌─────────────────────────────┐
│ [小封面] 书名 · 第 12 章  ◀ ▶ │ ← 顶栏：弱化，含章节切换
├─────────────────────────────┤
│   ……上一段文字（暗灰）        │
│   ▍正在朗读的句子（靛蓝高亮）  │ ← 跟读文本：自动滚动
│   下一段文字（浅灰白）……      │
├─────────────────────────────┤
│ ──●──·──·──·──·── 12:34/48:10│ ← 进度条 + 章节刻度点
│  ◀章  −15s  ▶  +15s  章▶    │ ← 控制簇（对称布局）
│  倍速  睡眠  章节            │ ← 次级入口
└─────────────────────────────┘
```

- **手势**：文本区左右滑 = 快速翻章（带边缘翻页提示）；进度条刻度拖动 = 跨章跳转；双指捏合进度条（移动）/ `Shift+←/→`（桌面）= 跨章略读模式（每章预览 30s）；
- **桌面快捷键**：`空格` 播放暂停、`←/→` 切章、`[ ]` ±15s、`Cmd/Ctrl+M` 打点笔记；
- **迷你条 ↔ 全屏**：Hero 动效展开/收起，跟读高亮位置保持。

### 5.2 跟读模式（两种形态，同一数据源）

| 形态 | 入口 | 布局 |
| --- | --- | --- |
| 播放器内文本视图 | 播放器默认态 | 文字为主体，封面退居顶栏 |
| 阅读器内播放态 | 阅读器右上角播放按钮 | 衬线排版为主体，播放按钮退居顶栏 |

- 高亮数据源：`echo-service` 转换管线产出的**句级 SRT**（`variant=chapter_srt` 按块获取），无字幕资产的书自动降级为纯封面模式；
- 当前句可点（跳转该句起播）、可长按（打时间戳笔记）；
- 播放器文本视图 ↔ 阅读器双向跳转，进度无缝。

### 5.3 章节导航与快速翻页

- 进度单位是**章节**：进度条渲染章节刻度点；顶栏与控制簇各有一组上一章/下一章；
- 跨块播放：echo-service 按章分块（≤30 分钟 MP3/WAV + SRT + `manifest.json`），播放器按块加载、自动续播，进度条刻度由分章清单计算得出。

### 5.4 任务流水线（下载 / 转换）

- 统一任务模型：`type ∈ {download, convert}`，状态机 `queued → running → done / failed`，失败可重试；
- 转换任务参数：TTS 引擎/音色（来自聚合 TTS 服务能力列表）/ 语速 / 章节范围；音色可先试听再提交；
- 章级进度实时可见（`第 12/48 章`），任务持久化可跨端同步；
- 完成通知点击直达播放；断点续传、暂停取消、队列优先级调整均支持。

### 5.5 时间戳笔记（桌面/平板优先，移动可查看）

- 播放中一键打点：笔记自动携带当前时间戳胶囊 `[02:15]`；
- 时间戳胶囊点击 → `seek()` 跳转音频位置；
- 笔记按章节分组，支持导出 Markdown。

### 5.6 后台与锁屏

- `just_audio` + `audio_service`：后台播放、锁屏/媒体通知控制、音频焦点（来电自动暂停）；
- 锁屏控件与 App 内播放器共用同一状态机，控制项一致（±15s + 倍速 + 章节名显示）。

## 6. 技术架构（Flutter）

### 6.1 选型与分层

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Flutter 3.22+（含 OpenHarmony 分支） | 单代码库六端：iOS / Android / HarmonyOS / macOS / Windows / Linux |
| 状态管理 | Riverpod | 全局播放器状态机、任务流、进度监听 |
| 音频 | `just_audio` + `audio_service` | 后台播放、锁屏控制、分块流式加载 |
| 存储 | Drift (SQLite) | 书籍元数据、双资产索引、播放进度、任务持久化、笔记 |
| 网络 | dio + echo-service API（Bearer Token） | 搜索/下载/转换任务、进度轮询、认证 |
| 桌面 | `window_manager` / `hotkey_manager` / `tray_manager` | 窗口、全局热键、托盘 |
| 主题 | `ThemeExtension` 消费 `design-tokens.json` | 强类型 Token，亮暗双态自动切换 |

### 6.2 双资产数据模型

```
Book
 ├── text_source   (EPUB/TXT：阅读器输入 + TTS 输入)
 ├── audio_assets  (已有音频 或 TTS 产物)
 │     ├── chapters[]  (分块：MP3 + SRT + manifest)
 │     └── voice/engine 元数据
 └── progress (统一进度：{chapter, block, offsetMs}，听看共享)
```

### 6.3 工程目录（feature-first）

```
lib/
├── core/        # 音频引擎、任务引擎、Drift、Riverpod、API client
├── design/     # ThemeExtension、Token 载入、字体
├── features/
│   ├── library/ │── discover/ │── search/
│   ├── player/  │── reader/    │── tasks/
│   ├── notes/   │── profile/   │── settings/
├── platform/    # MethodChannel 隔离层：音频/文件/系统播控；harmony 桥接
└── main.dart
```

**平台隔离层原则**：音频、文件、系统播控全部走抽象接口（`AudioPlayerAdapter` 等），主干平台用标准插件，鸿蒙未覆盖的插件以 ArkTS MethodChannel 补齐，不污染业务层。

### 6.4 关键架构约束

1. **任务中心 = 服务端 jobs 镜像**：转换在服务端执行（`echo-service` + `tts-service`），App 轮询 `/api/jobs` 呈现章级进度并支持取消，本地仅存镜像与展示状态；
2. **跟读渲染性能预算**：句级高亮跳变只重绘文本区（局部 `RepaintBoundary`），自动滚动用 `transform` 不用 `ScrollController.jumpTo` 暴力跳帧；
3. **响应式断点在 Widget 层实现**：`LayoutBuilder` + 600/1024dp，导航壳与播放器形态随断点切换，业务组件不感知具体平台；
4. **鸿蒙适配**：OpenHarmony Flutter SDK 构建；未适配插件用 MethodChannel 桥接 ArkTS；远期评估超级终端音频接力。
